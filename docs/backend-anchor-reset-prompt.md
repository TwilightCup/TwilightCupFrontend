# 后端任务：主控制台手动调整锚点 T（阅后即焚）

请先阅读并理解本文，将必要的协议说明保留在后端正式文档中，完成交接后删除本提示词文件。用户明确要求“阅后即焚”。本文件是临时交接文件，不要删除其他文件。

## 用户需求与工作边界

- 前端调试信息继续由原有显示／隐藏开关控制，增加锚点 T、现实时间及实际差值。
- 另设独立的锚点调整区域，不受调试信息开关影响：延迟 Δ 输入框，默认 30 秒，一个“应用”按钮。
- 当且仅当当前导播控制台是有效主 T 锚点时，输入框和按钮才可用；后端也必须验证权限。
- 点击应用，以点击时刻的控制台现实时间减去输入 Δ 秒作为目标 T：`target_t_us = (client_now_ms - delta_seconds * 1000) * 1000`，规范化为安全整数微秒。
- 用户需要能够增大或减小延迟，因此目标 T 可能向前，也可能向后。不是持续按墙上时钟覆盖每一个正常播放锚点。
- 只有 console 能参选和发布，stage 只接收；无主时舞台继续等待信号。保持单控制台多舞台、备用控制台不抢主和正常关闭后接管行为。
- 由你修改后端及后端测试、协议文档；前端实现由前端 agent 在收到协议后完成。除删除此临时交接文件外，不修改前端代码。

## 已查明的现状

- 后端 `src/twilightcupbackend/connection_manager.py` 的普通 frame_align 接收逻辑拒绝 `t < st.frame_align_t_us`。
- 前端 ExternalClock 的 lastInput / lastOutput，以及 AlignEngine 的 authorityFloor、已提交 T 和恢复逻辑，也维护单调时间下限。
- 当前换主 epoch 不代表允许时间倒退，因此仅修改普通帧包或递增现有 epoch 不足以完成安全重置。
- 正常上传的 T 来自已经共同呈现的画面；不能把“收到调整请求”当作“目标帧已经解码并显示”。
- 当前安全播放范围取决于媒体缓冲前沿，而不是现实时间。后端不能仅依据目标时间数值承诺媒体可用；前端会负责媒体范围、解码和呈现验证。

## 请设计并实现显式时间轴重置协议

以下是行为要求，消息名称与字段请结合已有框架决定，并在正式协议文档中写明。

1. **权限与并发**：仅允许同比赛、同导播账号的当前有效主 console 连接发起。校验连接身份、当前主角色、租约及请求所依据的 authority epoch／时间轴版本。stage、备用 console、断线旧主、失效租约或过期请求必须拒绝。
2. **独立的重置语义**：普通 frame_align 继续执行单调校验。只有明确接受的重置事务能建立新的时间轴并改变时间下限，禁止通过随意更改 source_id、scene 或普通包绕过校验。
3. **版本隔离**：采用显式 timeline/reset 版本，或具有明确重置标记及完整隔离语义的现有 epoch。所有相关帧、状态、快照、保活和接管消息都必须能区分重置前后。旧帧、旧租约状态、旧确认或迟到广播不能污染新时间轴。普通换主不能被误解为允许倒退。
4. **原子状态更新**：重置生效时一致更新权威快照、T 下限、序列校验、租约中的进度／接管确认依据及其他时间缓存，避免新的较小 T 被旧 floor 或旧 lease progress 拒绝。合法重置本身不应触发抢主或换主循环。
5. **准备与呈现**：明确目标准备、重置生效和媒体就绪之间的状态转换。主控制台及舞台需能在重置时清理旧时间下限并重建解码。重置通知不得复用旧 ready 标记宣称新画面已就绪；只有主端完成目标共同帧呈现后才能恢复正常推进。请明确准备失败、目标不可达、超时或主端中途断线时如何结束事务，不能无限挂起或错误恢复旧任期消息。
6. **响应与广播**：请求带可关联的 request_id；成功／失败均有明确响应与错误码。成功结果向包括发起者在内的所有同域控制台和舞台广播，含新版本、目标 T、当前主身份和必要时间元数据。定义重试／重复请求的幂等行为，不得重复重置。
7. **输入校验**：目标时间必须是有效 epoch 微秒安全整数。若接受 client_now_ms、delta_seconds，校验有限数值、单位和允许范围，并说明以哪个字段为准。目标取自点击时刻，不得到达服务端后悄悄换成另一个时间。说明合理的过去／未来范围限制与错误响应。
8. **重连与快照**：重连和新加入页面能从 state_sync 获取当前时间轴版本及重置状态，丢弃旧缓存；旧客户端或缺失版本的消息在重置后不能绕过隔离。请说明兼容策略。

## 后端验证要求

- 主 console 向前和向后重置均按协议成功；普通倒退 frame_align 仍被拒绝。
- stage、备用 console、失效主连接和过期版本请求被拒绝且不影响现有播放。
- 重置前在途帧、租约、确认消息在重置后不影响新 T、版本或主角色。
- request_id 重复提交、重置期间重复点击、准备失败／超时，以及主控制台中途关闭的行为可预测。
- 多舞台收到同一重置结果；新页面和重连页面快照一致。
- 第二控制台加入不抢主；重置后旧主关闭，合格备用控制台仍能依据新时间轴正确接管。
- 媒体等待保活不误报就绪、不恢复旧 T、不引发租约放弃循环。
